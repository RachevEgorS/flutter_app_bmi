# Калькулятор индекса массы тела

Учебное Flutter-приложение с экранами по предоставленным макетам.

## Запуск

Выполните `flutter pub get`, откройте папку проекта в VS Code, выберите Android-эмулятор и нажмите F5.
После изменения структуры приложения остановите предыдущий запуск и запустите заново.

## Файлы

- `lib/main.dart` — тема приложения и запуск `AuthScreen`.
- `lib/auth_screen.dart` — вход, проверка данных, переход к регистрации и калькулятору.
- `lib/registration_screen.dart` — отдельный экран регистрации с проверкой полей.
- `lib/bmi_screen.dart` — ввод роста в сантиметрах и веса в килограммах, расчёт результата.
- `lib/profile_screen.dart` — профиль и история выполненных расчётов.
- `lib/app_ui.dart` — общие цвета, карточки, поля, кнопки и нижняя панель.
- `lib/app_session.dart` — регистрация и вход через Supabase Authentication, данные пользователя и модель расчёта.
- `lib/supabase_config.dart` — URL проекта и публичный ключ Supabase.
- `lib/auth_error_message.dart` — сообщения об ошибках Authentication на русском языке.

## Регистрация и вход через Supabase

Подключён проект `https://dtisombcspixbigdwcex.supabase.co`.
Для SDK используется корневой URL без `/rest/v1/`: SDK сам добавляет пути Authentication и базы данных.
Ключ `sb_publishable_…` предназначен для клиентского приложения. Серверные ключи `secret` / `service_role` в приложение добавлять нельзя.
При необходимости конфигурация переопределяется через `--dart-define=SUPABASE_URL=…` и `--dart-define=SUPABASE_PUBLISHABLE_KEY=…`.

1. Откройте «Зарегистрироваться» и заполните имя, фамилию, email и пароль (минимум 6 символов; сервер может требовать более сложный пароль).
2. Нажмите «СОЗДАТЬ АККАУНТ». Приложение вызывает `auth.signUp`, передавая имя и фамилию как `user_metadata.name` и `user_metadata.surname`.
3. Если включено подтверждение email, откройте ссылку в письме Supabase. Затем вернитесь в приложение и войдите с этим email и паролем. Автоматический переход из письма в приложение на этом этапе не настроен.
4. Если подтверждение отключено, после регистрации можно сразу ввести пароль и войти.

Проверка подключения 24.10.2026: API принял публичный ключ; email-регистрация разрешена, подтверждение email включено. Реальные тестовые аккаунты при проверке не создавались, отправка писем не проверялась.

В Supabase → Authentication → URL Configuration должен быть настроен доступный Site URL, на который ведёт письмо подтверждения. В настройках почты должны быть разрешены письма нужным получателям (для внешних адресов может потребоваться собственный SMTP). Приложение использует настройки проекта, не изменяет их. Supabase иногда скрывает наличие существующего аккаунта и возвращает нейтральный ответ; приложение не обещает создание нового аккаунта, если сессия не получена.

Вход выполняется через `auth.signInWithPassword`. Ошибки отображаются под кнопкой, повторная отправка блокируется до завершения запроса. Старого учебного аккаунта и локального хранения паролей больше нет. SDK управляет сохранением токенов сессии; стартовый экран приложения пока остаётся экраном входа.

`UserProfile.id` содержит UUID пользователя из `auth.users.id`. Регистрация не создаёт пустые расчёты и не меняет существующую таблицу.

## Сохранение и история расчётов

Кнопка «РАССЧИТАТЬ» сохраняет в существующую таблицу `public.body_mass_index_calculations` рост, вес, неокруглённый индекс, рекомендацию и `user_id` из текущей сессии Authentication. Поля `id` и `created_at` не передаются: PostgreSQL применяет уже заданные `DEFAULT gen_random_uuid()` и `DEFAULT now()`. После вставки приложение получает сохранённую строку, включая UUID и серверную дату, и только затем показывает результат. Во время запроса повторные нажатия блокируются.

В предоставленной схеме `height` и `weight` имеют тип `bigint`. Поэтому принимаются положительные целые сантиметры и килограммы; `77,0` допустимо, `77,5` отклоняется без округления. Для дробных измерений потребуется отдельно изменить типы этих колонок. Схема таблицы приложением не меняется.

Профиль при каждом открытии загружает историю с сервера с фильтром `user_id = текущий пользователь`, сортировкой по серверной дате от новых записей к старым и дополнительной сортировкой по UUID. История загружается порциями по 50 записей; для продолжения есть «Показать ещё», для повторной загрузки — «Обновить историю». Показываются сохранённые индекс и рекомендация, а не заново вычисленные значения. Дата преобразуется в местное время устройства. После повторного входа и перезапуска доступна серверная история; пустая история и ошибка загрузки отображаются отдельно.

При ошибке сохранения результат не выдаётся за сохранённый. Если ответ сервера потерян, операция могла успеть выполниться: перед повторным нажатием следует проверить историю, чтобы не создать второй расчёт. Автоматических повторов вставки нет.

### Права доступа Supabase

Для работы нужны SELECT и INSERT для роли `authenticated` и политики RLS с проверкой `auth.uid() = user_id`. Фильтр в клиенте сам по себе не заменяет серверные ограничения.

Подготовлен файл `supabase/calculations_access.sql` для SQL Editor вашего существующего проекта. Он включает RLS, разрешает пользователю читать и добавлять свои строки и ограничивает доступ владельцем даже при наличии других разрешающих политик. Скрипт не создаёт таблицу, не изменяет типы колонок и не удаляет данные. Его можно выполнить повторно.

Этот SQL ещё не выполнен: предоставленный публичный ключ не даёт административного доступа к политикам базы. Проверена доступность REST endpoint таблицы без чтения пользовательских данных. Полная проверка записи и чтения в вашем проекте требует входа в реальный аккаунт.

Для ручной проверки: примените политики доступа, перезапустите приложение, войдите, рассчитайте ИМТ и откройте профиль. Затем повторно запустите приложение и войдите тем же пользователем — запись должна сохраниться. У другого пользователя эта запись отображаться не должна.

В профиле используется встроенный FlutterLogo в круге с зелёным контуром. Карточки занимают ширину экрана с отступами 16 логических пикселей. Отображаются имя и фамилия из Authentication; при первом входе история пустая.

## Расчёт

ИМТ = вес (кг) / рост (м)². Поддерживается запись целых значений с точкой или запятой (`77.0`, `77,0`); дробные значения отклоняются из-за типа `bigint` в существующей таблице.
Нулевые, отрицательные, пустые и нечисловые значения отклоняются.
История содержит только реально выполненные расчёты, новые идут первыми.
Категории ИМТ предназначены для взрослых от 20 лет и не являются диагнозом.
Тексты рекомендаций и семь диапазонов заданы по техническому заданию. Границы без пересечений: ИМТ ≤16; 16<ИМТ<18,5; 18,5≤ИМТ<25; 25≤ИМТ<30; 30≤ИМТ<35; 35≤ИМТ<40; ИМТ≥40. Категория определяется до округления, число отображается с точностью до двух знаков без конечных нулей. Нижняя панель имеет высоту 60 логических пикселей плюс системный безопасный отступ устройства.

## Проверка

`flutter analyze`

`flutter test`

Тесты вызывают настоящий Supabase SDK с подменённым HTTP-транспортом: проверяют регистрацию, метаданные, вход, подтверждение email, сохранение расчётов, серверные UUID/дату/рекомендацию, загрузку после новой сессии, фильтрацию пользователя, ошибки сервера, повторную отправку и закрытие экрана во время запроса. Данные в удалённом проекте не создаются. Это проверка клиентского поведения; удалённые RLS-политики этими тестами не проверяются.

`flutter build apk --debug --target-platform android-x64`

Последняя команда собирает APK для эмулятора x64; для телефона используйте `flutter build apk --debug`.
